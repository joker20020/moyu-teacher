# 学习档案规范（Archive Spec）

> 本文件规定本地 Markdown 学习档案的结构、文件职责、更新规则与跨会话恢复流程。

## 1. 档案位置与创建

- 档案创建在**当前项目/工作目录**下（用户开展学习的地方），目录名 `学习档案-<主题>`。
- 用技能自带脚本创建，保证结构一致：

```bash
python <skill目录>/scripts/init_archive.py --topic "主题" --path . --goal "目标" --level "基础"
```

- 脚本拒绝覆盖已存在的档案；已有档案时只能续写，不能重建（防止丢失历史）。
- 全部文件为 UTF-8 Markdown，学生可直接阅读；老师更新档案时保持各文件内已有的表格列与模板结构。

## 2. 目录结构与文件职责

```
学习档案-<主题>/
├── README.md           # 档案索引与"当前状态"面板（恢复会话的入口）
├── 00-学习计划.md       # 目标、起点、知识图谱、知识点清单、里程碑、间隔复习表
├── 01-学习日志.md       # 按时间追加的每轮教学记录
├── 02-掌握度台账.md     # 各知识点掌握等级 + 证据 + 升降级记录（权威状态）
├── 03-问答记录.md       # 有教学价值的问答与误区
├── 04-错题本.md         # 错题、错因、正解、重做安排
├── notes/              # 讲义笔记，NN-知识点名.md
├── exercises/          # 随堂练习 NN-*.md、阶段测验 阶段测验M*.md
├── reports/            # 阶段评估、结课报告、复习计划
└── 答疑记录/            # 角色 C 课后答疑，一问一份 YYYY-MM-DD-问题简述.md（含索引 README）
```

单一事实来源原则：

- "学到哪、学得怎么样"只看 `README.md` + `02-掌握度台账.md`；
- "发生过什么"只看 `01-学习日志.md`；
- 计划类信息只看 `00-学习计划.md`。
- 同一信息不要在多处各写一套不一致的版本；其他文件需要引用时链接过去。

## 3. 掌握度等级与证据规则

| 等级 | 名称 | 升级所需行为证据 |
|---|---|---|
| L0 | 未接触 | — |
| L1 | 初识 | 能辨认概念、照提示复述要点 |
| L2 | 理解 | 不看材料用自己的话解释清楚，答对概念性/辨析性提问 |
| L3 | 应用 | **独立**（不看笔记、不看答案）做对基础应用题 |
| L4 | 精通 | 独立做对变式/综合题，或通过费曼讲解把他人讲懂 |

铁律：

1. **无证据不升级**。"讲过了""学生点头了"不是证据；证据是学生的口头回答或独立练习结果。
2. **就高不就低，也不虚高**：L3 必须有独立练习全对（或按测验评分标准达到约定正确率，默认 ≥80%）。
3. **降级要果断**：复习答错、关键概念遗忘、同类题再错，降 1 级并重新验证；间隔复习重新起算。
4. 每次升降级都在台账"升降级记录"写明日期、变化、依据。
5. 知识点完成线默认是 **L3**；核心/重点知识点（计划中标"高"重要度的）要求 L4。

## 4. 各文件填写规范

### README.md（状态面板）

- 每次学习结束更新：最近学习日期、当前进度（x/N 及百分比，按 ≥L3 计完成）、当前位置、下一步动作、到期/待复习内容。
- 保持表格形态，信息保持一两行内，详情链接到具体文件。

### 00-学习计划.md

- 备课阶段一次性建立，之后允许迭代，迭代时在日志中注明调整原因。
- 知识点清单要可教学：每个知识点是"一节课或半节课能走完一个循环"的粒度，避免章节级大颗粒。
- 知识图谱用 mermaid 或缩进列表表达先修关系；教学顺序必须尊重先修关系。
- 复习表随学习推进持续填写，不要等结课才补。

### 01-学习日志.md

- 每轮学习追加一条，使用文件内模板；标题含日期、次数、知识点。
- 必须记录**学生的真实回答要点与练习对错**，以及掌握度变化及依据；禁止只写"讲解了 X，学生表示理解"。
- 一次学习跨越多个知识块时，可在一条日志中分小节记录。

### 02-掌握度台账.md

- 知识点总表每行：知识点 ｜ 当前等级 ｜ 上次验证日期 ｜ 证据 ｜ 下次复习日期。
- "证据"栏简明引用，如"提问：能解释闭包，例 2 正确""练习 ex03 第 1、3 题对，第 2 题错"。
- 与日志保持一致：日志里写了等级变化，台账必须同步。

### 03-问答记录.md

- 只记有复用价值的内容：典型误区、精彩的引导过程、学生自己悟出的关键结论。
- 记录学生回答时用要点/原话，不美化、不篡改错误。

### 04-错题本.md

- 每道错题：题目、学生作答、错因标签、错因分析、正确思路、同类练习指引、重做安排、状态。
- 重做日期对应间隔复习；三次重做均正确可标 ✅ 已过关，记录保留不删除。

### 答疑记录/（角色 C 产出）

- 一问一份，命名 `YYYY-MM-DD-问题简述.md`，由 `scripts/init_qa.py --archive <本档案目录>` 生成并登记索引；
- 记录是一页内的复习卡片（原问→疑问定位→简洁解答→复习自测→跟进），写作规范见 `references/qa-playbook.md`；
- 答疑当场的复述/自测结果是有效行为证据，可据此更新台账并在日志追加一行；**仅"来提问"不构成降级依据**；
- 同一知识点短期内被答疑 ≥2 次，视为掌握缺口信号，安排角色 A 的讲解与变式练习。

### notes/、exercises/、reports/

- 命名：`NN-知识点名.md`（NN 为学习路线序号，两位数字）；测验与报告带日期或里程碑编号。
- 讲义与练习的模板见 `references/deliverable-templates.md`。
- 练习文件中题目与答案分区放置（答案放在文末"参考答案与解析"部分），避免学生提前看到。

## 5. 跨会话恢复流程

每次被唤起继续教学时，**先恢复、后开口**：

1. 在工作目录查找 `学习档案-*/README.md`：
   - 找不到 → 新主题，走 SKILL.md 的"启动与备课"流程；
   - 只有一个 → 直接恢复；
   - 有多个 → 让学生指定本次学哪个（可列出各档案的主题与当前位置）。
2. 依次读取：`README.md`（状态面板）→ `02-掌握度台账.md`（权威等级）→ `01-学习日志.md` 末尾 1~2 条（最近发生了什么）→ `00-学习计划.md`（下一步是什么）。
3. 检查台账"下次复习日期"与错题本到期重做项，确定本次是否先复习。
4. 用一句话向学生复述恢复到的状态并确认："我们上次学到 X，你掌握了 Y，Z 练错了一道；今天先复习 Z 再进入 W，可以吗？"
5. 学生确认后再开始教学循环；若学生表示实际情况与档案不符（比如其实已经忘了），以现场小测为准修正台账。

## 6. 多主题与档案维护

- 不同主题分别建档，不要合并；相关主题可在学习计划中互相链接。
- 档案只增不删历史记录；计划变更用"调整说明"标注，不抹掉旧轨迹。
- 阶段评估、结课时检查档案一致性：README 进度、台账等级、日志证据、错题状态四处对得上再出报告。
- 结课档案保留，并在结课报告中给出后续复习日程；学生回来复习时继续使用同一档案。
