## 1. 记录位置与创建

- 记录创建在**当前项目/工作目录**下，目录名 `评分记录-<作业名>`。
- 用技能自带脚本创建，保证结构一致：

```bash
python <skill目录>/scripts/init_grading.py --assignment "第三单元测验" --path . \
    --subject 数学 --students "张三,李四" --total 100
```

参数：`--assignment`（必填）、`--path`（默认当前目录）、`--subject`、`--students`（逗号分隔，可后补）、
`--total`（默认 100）、`--pass`（合格线，默认 60）、`--date`（默认今天）。

- 脚本拒绝覆盖已存在的记录；已有记录只能续写，不能重建。
- 全部文本文件为 UTF-8（无 BOM）、LF 换行；**导出的 CSV 为 UTF-8 BOM**，保证 Excel 直接打开中文不乱码。

## 2. 目录结构与文件职责

```
评分记录-<作业名>/
├── README.md              # 索引与评分进度面板（学生名单、状态、标准版本、问题清单）
├── 00-作业与评分标准.md     # 题目、参考答案、采分点/量表、统一扣分口径、修订记录（评分依据）
├── grades.json            # 结构化成绩数据（唯一权威分数来源，脚本校验与导出）
├── 01-成绩总表.md          # 由脚本从 grades.json 重新生成，不要手改
├── 批改/
│   └── 评分反馈-<姓名>.md   # 每人一份；脚本生成骨架，评分官补充亮点/建议/总评
├── exports/
│   ├── 成绩总表.csv          # 由脚本生成，Excel 可直接打开
│   ├── 批次总评-<作业名>.md   # --review-kit 生成数据骨架，评分官补总体评价/问题点/改进方向
│   └── 讲解课教案-<作业名>.md # --review-kit 生成（含必讲题清单与过程表），评分官补精讲脚本
│       # 讲解课 PPT 不由脚本生成：教案定稿后整理需求简报，派发 ppt 技能/子 agent 制作，
│       # 交付本地 讲解课PPT-<作业名>.pptx（可编辑，用户要求时再出 PDF），路径回填教案
└── 原始作答/               # 原始作答文件副本/转换件（PDF、图片、文档），留存备查
```

单一事实来源原则：

- **分数只认 grades.json**；Markdown 总表、CSV、反馈单中的分数都由它生成，手改这些文件无效；
- **评分依据只认 `00-作业与评分标准.md`**（含修订记录）；
- 原始作答以 `原始作答/` 留存件为准；定性评语写在反馈单里。

## 3. grades.json 数据格式

脚本初始化时生成骨架；评分官随评随填。完整示例：

```json
{
  "schema_version": 1,
  "assignment": {
    "name": "第三单元测验",
    "subject": "数学",
    "date": "2026-10-07",
    "total_score": 100,
    "pass_score": 60,
    "grade_boundaries": [
      {"grade": "优秀", "min": 90},
      {"grade": "良好", "min": 80},
      {"grade": "合格", "min": 60},
      {"grade": "不合格", "min": 0}
    ],
    "questions": [
      {"id": "1", "title": "选择题：一元二次方程识别", "type": "objective",  "max_score": 5,  "knowledge": "一元二次方程概念"},
      {"id": "2", "title": "计算题：求根公式",       "type": "subjective", "max_score": 15, "knowledge": "求根公式"}
    ]
  },
  "students": [
    {
      "name": "张三",
      "student_id": "20260101",
      "status": "graded",
      "items": [
        {
          "qid": "1",
          "score": 5,
          "verdict": "正确",
          "evidence": "选择 B，与标准答案一致",
          "awarded": "",
          "deductions": "",
          "note": ""
        },
        {
          "qid": "2",
          "score": 10,
          "verdict": "部分正确",
          "evidence": "学生写 Δ=9（正确为 Δ=49），后续按 9 代入；未写检验",
          "awarded": "正确写出求根公式并完成代入流程（P2、P4 流程分）",
          "deductions": "判别式计算错误扣 2（P3）；两根随 Δ 错误各扣 1.5；未检验扣 0（本题不要求）",
          "note": ""
        }
      ],
      "adjustment": {"delta": -5, "reason": "迟交一天，按课前公布规则扣 5 分"},
      "comment": ""
    },
    {"name": "李四", "student_id": "20260102", "status": "absent", "items": [], "comment": ""}
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | 固定 `1` |
| `assignment.name/subject/date` | str | 作业名、科目、布置或评分日期（YYYY-MM-DD） |
| `assignment.total_score` | num | 卷面满分；不填时默认 = 各题满分之和 |
| `assignment.pass_score` | num | 合格线，默认 60；不设合格线填 null |
| `assignment.grade_boundaries` | array | 等级档：`grade` 名称 + `min` 该档最低分（含），从高到低排列；可省略 |
| `questions[].id` | str | 题号，**全卷唯一**，如 "1"、"2(1)"、"三" |
| `questions[].title` | str | 题干简述（便于总表阅读，不必全文） |
| `questions[].type` | str | `objective`（客观）/ `subjective`（主观） |
| `questions[].max_score` | num | 该题满分，≥0 |
| `questions[].knowledge` | str | 考查知识点（选填，用于班级分析与学习档案联动） |
| `students[].name` | str | 学生姓名，**必须有**；同名学生在姓名后加区分（如"张伟（1班）"） |
| `students[].student_id` | str | 学号（选填） |
| `students[].status` | str | `graded` 已评（默认）/ `pending` 待评 / `absent` 缺考 / `exempt` 免修 |
| `students[].items[]` | array | 逐题记录，每题一条；`absent/exempt` 留空数组 |
| `items[].qid` | str | 必须与 questions 中的 id 完全一致 |
| `items[].score` | num | 该题得分，0 ≤ score ≤ 该题满分，计分粒度与评分标准一致 |
| `items[].verdict` | str | `正确` / `部分正确` / `错误` / `未作答` / `无法辨认` |
| `items[].evidence` | str | **学生作答原文摘录或位置**（如"第 2 页倒数第 3 行：……"），客观题可简写 |
| `items[].awarded` | str | 命中的采分点（主观题必填） |
| `items[].deductions` | str | 未命中采分点与扣分说明（有扣分时必填） |
| `items[].note` | str | 其他备注（复评改分原因、疑似问题等） |
| `students[].adjustment` | obj | 卷面调整分：`delta`（正数加分/负数扣分）+ `reason`（必填）；无调整省略此字段 |
| `students[].comment` | str | 总评（也可只写在反馈单里，两处保持一致） |

计算口径（由脚本执行，不需手算）：

- 原始总分 = 各 items 得分之和；最终总分 = 原始总分 + adjustment.delta；
- 得分率 = 最终总分 / 卷面满分；
- 等级 = 满足 `min ≤ 最终总分` 的最高档；合格判定对照 pass_score；
- `absent/exempt` 不计入任何统计，总表显示"缺考/免修"。

## 4. 录入规范

1. **边评边录**，评完一份录一份；`status` 随进度置 `pending → graded`。
2. 客观题也要逐题留痕（verdict + 简短 evidence），不能只填总分。
3. 未作答的题填 `score: 0`、verdict `未作答`；无法辨认填 `无法辨认` 并在 note 说明，同步进 README 问题清单。
4. 录完一个学生立即自查：items 题数与 questions 一致、得分未超满分。
5. 姓名、题号统一用建档时的写法，不在 grades.json 里临时改题号；确需调整先改 questions 并全局同步。
6. JSON 保持合法（字符串内换行用 `\n`，引号转义）；脚本解析失败会报错并中止，按提示修复。

## 5. 导出脚本与校验规则

```bash
# 完整导出（总表 MD + CSV + 每人反馈单骨架 + 讲评产出包两份骨架）
python <skill目录>/scripts/export_grades.py "评分记录-第三单元测验/grades.json" \
    --feedback --review-kit

# 仅重新生成成绩总表与 CSV（不触碰已写好评语的反馈单与讲评文档）
python <skill目录>/scripts/export_grades.py "评分记录-第三单元测验/grades.json"

# 严格模式：任何警告都按失败处理（适合交付前终检）
python <skill目录>/scripts/export_grades.py grades.json --feedback --review-kit --strict
```

`--review-kit` 在 `exports/` 生成两份讲评骨架（批次总评、讲解课教案）；
PPT 不由脚本生成，教案定稿后按 `review-lesson-kit.md` 第 5 节派发 ppt 技能制作：
统计、分数段、逐题得分率、🔴必讲/🟡选讲题目、匿名错误样本由脚本预填；
文件已存在默认跳过（保护已补全内容），`--force-kit` 覆盖（先备份）。

硬错误（退出码 1，不产出文件）：

- JSON 解析失败、缺少 assignment/questions/students 结构；
- 题号重复或缺失、题目满分为负；
- item 的 qid 不存在；得分超出 [0, 满分]；
- adjustment 缺 reason；最终总分超出 [0, 卷面满分]；
- graded 学生缺少整题记录（防止漏录）。

警告（打印汇总，`--strict` 下转为失败）：

- `pending` 学生尚未评完；
- 各题满分之和与 total_score 不一致；
- 同名学生、学号缺失；
- 主观题缺 awarded/deductions、任何题缺 evidence。

脚本每次运行都**重新生成** `01-成绩总表.md` 与 `exports/成绩总表.csv`；
反馈单已存在时默认跳过（保护已写评语），需要重生成用 `--force-feedback`（会覆盖，先自行备份）。

## 6. 导出物格式

### 6.1 `01-成绩总表.md`

- 头部：作业名、科目、日期、满分、合格线、评分时间、应评/已评/缺考人数；
- 明细表列：学号 ｜ 姓名 ｜ 状态 ｜ 第 1 题(满分) … 第 n 题(满分) ｜ 调整 ｜ 总分 ｜ 得分率 ｜ 等级 ｜ 合格；
- 表后统计：平均分、中位数、最高/最低、合格率、等级人数分布、**逐题平均得分与得分率**（得分率 <60% 的题自动标注 ⚠️ 作为讲评重点）。

### 6.2 `exports/成绩总表.csv`

- 列与总表明细一致，UTF-8 **带 BOM**，逗号分隔，Excel/WPS 双击直接打开；
- 缺考/免修学生总分列留空、状态列写"缺考/免修"，避免被当成 0 分拉低平均。

### 6.3 讲评产出包（批量作业）

`--review-kit` 生成的批次总评、讲解课教案见第 8 节；
写作标准、教学设计方法与 PPT 需求简报/派发纪律见 `references/review-lesson-kit.md`。

## 7. 评分反馈单结构

`批改/评分反馈-<姓名>.md` 由脚本生成骨架（基本信息、成绩总览、逐题表格与证据），
评分官补写"亮点 / 问题与建议 / 总评"。写法遵循 `grading-playbook.md` 第 7 节。

```markdown
# 评分反馈：<作业名> · <姓名>

- 学号： ｜ 班级/科目： ｜ 评分日期：
- 评分依据：00-作业与评分标准.md v1.0
- **总分：xx / 100 ｜ 得分率：xx% ｜ 等级：xx ｜ 是否合格：是/否（缺考/免修）**
- 卷面调整：−5（迟交一天，按规则扣分） ｜ 无调整则删除本行

## 逐题得分
| 题号 | 题目 | 满分 | 得分 | 判定 | 考查知识点 |
|---|---|---|---|---|---|
| 1 | … | 5 | 5 | 正确 | … |

## 逐题详评
### 第 2 题（10 / 15）· 部分正确
- **你的作答**：（脚本带入 evidence 原文摘录）
- **给分点**：命中 P2、P4 流程分……
- **扣分说明**：Δ 计算错误扣 2；……
- **订正指引**：（评分官写：回到哪个知识点、怎么改）

## 亮点
（具体到题/步骤的肯定，脚本留空待补）

## 主要问题与改进建议（按优先级，2~4 条）
1. 问题 → 归因 → 下一步动作

## 总评
（一段话：水平定位 + 鼓励 + 下一阶段重点）

---
如对评分有疑问，请在老师规定时限内注明题号申请复核。
```

## 8. 讲评产出包：批次总评、教案与 PPT

批量作业（≥3 人）在成绩定稿后，用 `--review-kit` 生成两份数据骨架并补全；
**写作方法、完整模板与 PPT 派发流程见 `references/review-lesson-kit.md`**，本节只规定数据契约与文件职责。

| 文件/产物 | 脚本预填 | 评分官补全/负责 |
|---|---|---|
| `exports/批次总评-<作业名>.md` | 人数与均分等指标、分数段/等级分布、逐题得分率与优先级、问题点占位（含匿名错误样本） | 总体评价（达成度/亮点/分层）、问题点四要素、改进方向与时间节点 |
| `exports/讲解课教案-<作业名>.md` | 学情数据、🔴必讲/🟡选讲/🟢略讲清单、按必讲题预排的教学过程表、逐题错误样本 | 可检验教学目标、逐题精讲问题串与正解、方法提炼、变式题（带答案采分点）、分层作业、课后反思 |
| `exports/讲解课PPT-<作业名>.pptx`（默认；用户要求时再出 `.pdf`） | **不由脚本生成任何固定文件** | 教案定稿后按 review-lesson-kit 第 5 节整理需求简报，**派发 ppt 技能（子 agent）制作并导出本地文件**；提供数据素材，收到文件后亲自打开按验收清单核对（可打开、可编辑、无乱码），路径回填教案；在线幻灯片须导出为本地文件，不仅交付链接 |

数据与纪律：

- 总评与教案的数字全部来自 grades.json（与 `01-成绩总表.md` 同源），不得另造；PPT 数字必须与总表一致；
- 公开讲评材料匿名脱敏（脚本错误样本以"样本①"编号，不含姓名）；
- 讲题优先级：得分率 <60% 🔴必讲、60%~80% 🟡选讲、≥80% 🟢略讲/个别辅导；
  45 分钟课聚焦 2~4 个必讲点，脚本在教案中对超时风险给出提示；
- PPT 由 ppt 技能制作、交付本地 `.pptx`（可编辑）/`.pdf`，评分官对内容负责：图表用真实数据、正文每页 ≤6 行、讲稿入备注、作答截图涂掉姓名学号、不编造题目数据；交付前必须亲自打开文件核对；
- 单份或 2 份以下作业不出讲评产出包，按 review-lesson-kit 第 6 节出个人错题讲解清单；
- 再测安排与学习档案回填按第 10 节执行，讲评后用再测数据验证改进效果。

## 9. 改分与复评流程

1. 复核或申诉后确认改分：**只改 grades.json**（同步更新该 item 的 score/verdict/note，note 写明"复评改分：原因 + 日期"）；
2. 重新运行导出脚本，总表、CSV、反馈单全部刷新；
3. 已发出的旧成绩如与新成绩不一致，明确告知老师/学生改动了哪题、改动前后分数与依据；
4. 评分标准修订导致的批量改分，先在 `00-作业与评分标准.md` 修订记录登记，并对全部已评份数回溯重评；
5. 任何删除成绩记录的操作都不允许，错误记录用追加说明更正，保留审计轨迹。

## 10. 与学习档案的交接格式

当作业服务于某个 `学习档案-<主题>/`（教学导师角色建立）时，评分完成后追加：

1. **错题本 `04-错题本.md`**：按其模板逐题登记错题（题目、学生作答、错因标签、错因分析、正确思路、重做安排）；
2. **掌握度台账 `02-掌握度台账.md`**：依据 questions[].knowledge 映射知识点，按实测更新等级并在升降级记录注明"评分记录-<作业名> 第 x 题证据"；
3. **学习日志 `01-学习日志.md`**：追加一条"作业/测验评讲"记录，含总体表现、共性问题、补讲安排；
4. **学习计划 `00-学习计划.md`**：写入补讲与再测里程碑；
5. 交接时只引用 grades.json 中的分数与证据，学习档案中不另造成绩表。
