# 批次讲评产出包指南（Review Lesson Kit）

> 一批作业（建议 ≥3 份；单份作业走个人反馈即可）评分完成后，评分官不只交成绩，
> 还要交一套"后半篇文章"：① **批次总评**（总体评价、问题点、改进方向）；
> ② **习题讲解课教案**；③ **讲解课 PPT**。本文件规定三者的内容标准、模板与制作流程。
> 前两份文档的数据部分由 `export_grades.py --review-kit` 用 grades.json 真实数据预填骨架，
> 定性分析与教学设计由你（agent）依据逐题证据补全；
> **PPT 不使用脚本生成固定文件**：教案定稿后由你整理需求简报，**派发已安装的 ppt 技能（建议交给子 agent 执行）**
> 按其自身流程制作，**交付目标是本地可编辑的 `.pptx` 文件（默认）或 PDF**，存入 `exports/`，你负责提需求与验收。
> **禁止凭空写"整体掌握良好"之类无数据支撑的结论。**

## 1. 产出清单与制作流程

| 产出物 | 存放/交付 | 产生方式 | 你负责 |
|---|---|---|---|
| 批次总评 | `exports/批次总评-<作业名>.md` | 脚本 `--review-kit` 预填统计与逐题表 | 总体评价、问题点、改进方向 |
| 讲解课教案 | `exports/讲解课教案-<作业名>.md` | 脚本 `--review-kit` 预填学情数据、必讲/选讲题清单 | 教学目标、精讲脚本、变式题、环节设计 |
| 讲解课 PPT | `exports/讲解课PPT-<作业名>.pptx`（默认，本地可编辑）；用户要求时再出同名 `.pdf` | **你整理需求简报，派发 ppt 技能/子 agent 制作并导出本地文件**，本技能不生成固定 PPT 文件 | 写需求、供数据、验收文件、登记路径 |

制作流程：

```
grades.json 定稿 → export_grades.py --review-kit 生成总评与教案两份骨架
→ 汇总逐题证据写批次总评 → 选讲题、写教案精讲脚本与变式题
→ 按第 5 节整理 PPT 需求简报 → 派发 ppt 技能（子 agent）制作 → 按清单验收 → 交付并回填学习档案
```

纪律：

- 总评、教案、PPT **共用同一套数字**（平均、得分率、等级分布以 `01-成绩总表.md` 为准），不另造数据；
- 引用学生作答一律**匿名**（"有同学……"或编号样本①），公开讲评不暴露姓名；
- 讲题数量克制：一节 40~45 分钟讲评课聚焦 **2~4 个高频错点/题目**，其余问题用个别反馈解决；
- 教案与 PPT 是讲评课的"剧本"，不是把答案再抄一遍——核心是错因诊断与方法迁移；
- **PPT 的制作主体是 ppt 技能，不是本技能的脚本**：你只输出需求与素材，不手工拼固定 PPT 文件。

## 2. 批次总评的写法

### 总体评价（结论先行，数据支撑）

- 先用 2~3 句话给整体定位：对照作业目标与合格线，班级整体处于什么水平、是否达成预期；
- **班级亮点**：哪些题/知识点得分率高、出现了哪些好解法，具体到题与做法（用于讲评正向强化）；
- 客观陈述分层情况：头部/中部/薄弱各占比，避免只盯不及格；不公开排名。

### 问题点（按影响面排序，3~5 个）

每个问题点写清四要素，缺一不可：

1. **问题表现**：对应题号、失分人数/比例、得分率（从总表取数）；
2. **典型证据**：1~2 条匿名作答摘录或错误类型（从 grades.json 的 evidence/deductions 汇总）；
3. **错因归类**：概念不清 / 方法不会 / 审题失误 / 计算操作失误 / 表达规范 / 知识遗忘 / 时间管理；
4. **根源判断**：是教学未到位、题目偏难超纲、前置知识缺口，还是训练量不足——区分清楚再开药方。

注意：同一道题的不同错误可能属于不同问题点，按"错因"而不是按"题号"归并；
若某题低分是题目本身问题（超纲/歧义），明确写出，不计学生责任。

### 改进方向（可执行、有时限、分层）

- **教学侧**：讲评课要解决什么、哪些知识点需要重讲/补前置、教学方法调整、何时变式再测；
- **学生侧**：共性订正要求（如"人人重做第 3 题并写出错因"）、分层任务（薄弱生保底、中等生熟练、拔尖生拓展）；
- **个别辅导名单**：哪几位学生、对应什么知识点（来自反馈单，不在公开文档点名批评）；
- **时间节点**：讲评日期、变式练习日期、复测日期（可算出具体日历日）；
- 若存在 `学习档案-*`，改进方向同步进学习计划与复习安排（见 grading-spec 第 10 节）。

## 3. 习题讲解课的设计原则

习题讲评课是**课**，不是对答案。遵循教学导师角色的教学法（`teaching-playbook.md`）：

1. **以学定教，少讲精讲**：学生自己能订正的不讲；错误率低（得分率 ≥80%）的题只给答案或个别辅导；
   课堂时间留给得分率 <60% 的必讲题与典型错因（脚本已在教案骨架按 🔴必讲 / 🟡选讲 / 🟢略讲 标注）。
2. **先暴露后诊断**：呈现匿名典型错误 → 用问题串追问"这一步为什么错、当时怎么想的"，
   让学生自己识别错因（提示阶梯），而不是老师直接宣布正确答案。
3. **回到方法，不止于一题**：每题讲完提炼通用步骤/判别规则，再配一道**变式题当堂独立完成**
   （闭卷、1~3 分钟），用行为证据确认纠错生效；变式题与原题同构但情境/数据不同。
4. **错误不传导的公平性要讲**：若评分中适用了"前错后对给后续分"，讲评时点明，引导学生关注方法而非只盯分数。
5. **学生主体**：安排自评自标、邻座互讲、学生复述错因等活动；教师讲授累计不超过课时一半。
6. **闭环**：讲评 → 当堂变式验证 → 分层订正作业 → 数日后变式再测；再测数据与本次对比，验证改进。

课时与节奏参考（45 分钟）：数据反馈与自评 5′ → 典型错题精讲 22′（2~3 题，每题含变式）
→ 综合变式巩固 10′ → 小结与作业 8′。题多则排 2 课时或讲最核心的，不赶进度满堂灌。

## 4. 教案模板与填写要求

`export_grades.py --review-kit` 已生成带数据的教案骨架，按下述要求补全：

```markdown
# 习题讲解课教案：<作业名>

## 一、基本信息
- 授课对象 / 课时（建议 40~45 分钟）/ 课型：习题讲评课 / 授课日期

## 二、学情依据（脚本预填，不改动数字）
- 成绩分布、合格率、逐题得分率与必讲/选讲标注

## 三、教学目标
1. 知识目标：能纠正并正确理解 <薄弱知识点>（对应第 x 题）
2. 能力目标：掌握 <方法/步骤>，能独立完成同构变式题
3. 习惯与规范目标：如检验、单位、审题圈画（视问题点）
（目标必须可检验：课后变式题正确率达到 x%）

## 四、教学重点与难点
- 重点：错误最集中的 2~4 个点；难点：错因根源（如概念辨析、建模转化）

## 五、教学过程
| 环节 | 时长 | 教师活动 | 学生活动 | 设计意图 |
|---|---|---|---|---|
| 数据反馈·自评 | 5′ | 公布分布与亮点；发回作业自标错题 | 标注"会而做错/真不会" | 主动回忆、区分错因 |
| 错题精讲 1 | 8′ | 呈现典型错误→问题串诊断→推导正解→提炼方法 | 找错、回答、复述方法 | 纠错归因 |
| 变式验证 1 | 3′ | 出示变式题 | 闭卷独立完成，同桌互批 | 行为证据验证 |
| …（按必讲题重复） | | | | |
| 综合巩固 | 8′ | 2 道混合变式 | 独立完成、展示思路 | 迁移 |
| 小结·作业 | 5′ | 引导学生归纳"防错清单" | 说收获、记作业 | 费曼输出 |

## 六、逐题精讲脚本（每个必讲/选讲题一份）
### 第 x 题（得分率 xx%，🔴 必讲）
- 题面（PPT 呈现）：
- 典型错误（匿名摘录 2~3 种，脚本清单 + grades.json 证据）：
- 错因诊断问题串：
  1. "这位同学第一步做了什么？题目条件都用上了吗？"
  2. "这两个概念/步骤的区别是什么？"
- 正确思路推导（板书关键步骤，留白让学生补）：
- 方法提炼（一句话规则/步骤卡）：
- 变式题（同构换情境，附答案与采分点）：
- 预设学生反应与对策（仍答错→回退到哪个提示）：

## 七、课件
- 板书分区：左=错因诊断，中=正确方法，右=变式；
- 讲解课 PPT 由 ppt 技能按第 5 节需求简报制作，交付本地 `.pptx`（或 PDF）；文件路径回填此处：
  `exports/讲解课PPT-<作业名>.pptx`

## 八、分层作业
- 全体：错题订正（写错因 + 正确过程）+ 变式题组 x 题
- 薄弱名单（教师掌握，不公开）：补前置知识 + 基础题
- 学有余力：拓展/综合题 1~2 道

## 九、教学反思（课后填）
- 当堂变式正确率 / 仍未解决的问题 / 再测安排与日期
```

变式题编写要求：与错题考查同一采分点、难度相当或略低、情境新颖（避免背答案）；
出题时一并写答案与采分点，格式可复用 `deliverable-templates.md` 第 3 节练习模板。
**教案第六部分（逐题精讲脚本）与变式题答案就是 PPT 的内容来源**，必须先于 PPT 定稿。

## 5. PPT：需求简报与派发 ppt 技能

### 5.1 原则

- PPT 的制作主体是**本环境已安装的 ppt 技能**；本技能**不生成、不手写固定 PPT 或逐页大纲文件**。
- **交付目标是本地文件**：默认交付**可编辑的 `.pptx`**（老师课后能自行修改），用户明确要求时
  再导出/改交付 **PDF**；文件统一存入评分记录的 `exports/`，命名 `讲解课PPT-<作业名>.pptx`（或 `.pdf`）。
  **不把在线幻灯片链接作为最终交付物**：若所用 ppt 技能只能先产出在线幻灯片，要求制作方
  导出/下载为 `.pptx`（必要时再转 PDF）后交付本地文件。
- 推荐做法：教案定稿后，你把完整的**需求简报**派发给一个子 agent（或直接调用 ppt 技能的会话），
  让其加载 ppt 技能、按 ppt 技能自身的规范流程制作并导出本地文件；你提供需求、数据与素材，并在收到文件后验收。
- 你对内容正确性负责：ppt 技能负责视觉与工程实现，**题目、数据、错因、正解、变式以你的总评与教案为唯一依据**，
  不得让制作方自行编造。

### 5.2 派发前必须齐备的素材

1. `01-成绩总表.md`：分布、合格率、逐题得分率（图表数据）；
2. `exports/批次总评-<作业名>.md`：总体评价、亮点、问题点、改进方向（已定稿）；
3. `exports/讲解课教案-<作业名>.md`：逐题精讲脚本（典型错误、问题串、正解、方法卡）与变式题（含答案）；
4. 匿名素材：需要呈现的学生作答截图，先涂掉姓名、学号等身份信息。

### 5.3 PPT 需求简报模板（复制后填好，随派发完整交给 ppt 技能/子 agent）

```markdown
【讲解课 PPT 制作需求】
一、任务背景
- 课题：<作业名> 习题讲评课 ｜ 授课对象：<科目/班级> ｜ 日期：<日期> ｜ 课时：45 分钟
- 交付形式：**本地可编辑 `.pptx` 文件**（默认）；<如用户要求 PDF，写：同时/改为导出 PDF>
- 保存位置与命名：评分记录 `exports/讲解课PPT-<作业名>.pptx`（PDF 同名换后缀）；
  若只能先生成在线幻灯片，必须导出/下载为该本地文件后再交付，不接受仅给在线链接
- 字体与兼容：使用常见中文字体（如微软雅黑/思源黑体），避免在无该字体的电脑上排版错乱

二、受众与风格
- 受众：<年级/班级>学生；课堂投影使用，要求字号大、一页一要点、正文每页 ≤6 行
- 风格：清晰、朴素、教学向；必讲题（低得分率）用红色/警示色突出；避免花哨动画

三、建议页序与每页内容（约 13~20 页，可按必讲题数量伸缩）
1. 封面：课题、班级、日期、主讲
2. 本课导航：作业反馈→错题诊断→正解方法→变式巩固→作业要求
3. 作业总体情况：实评/缺考人数、平均/中位/最高/最低、合格率（数字卡片）
4. 成绩分布：分数段柱状图 + 等级饼图（数据见素材①，原样使用不得改数）
5. 逐题得分率全景：横向条形图，必讲题（得分率<60%）红色标注
6. 班级亮点：<从批次总评第二节摘取>
7. 问题总览：3~5 个问题点关键词 + 对应题号（从批次总评第三节摘取）
8~n. 每个🔴必讲题 2~3 页：
   (a) 典型错误：匿名作答截图/摘录（素材④），只呈现现象不先给答案
   (b) 错因诊断与正确思路：左右对比版式；诊断问题串与正解分步（取自教案第六部分）
   (c) 方法提炼 + 变式题：方法卡一页可拍照；变式题干（答案与采分点供备注，不放正文）
n+1. 防错清单：每条对应一个必讲点
n+2. 改进方向与分层作业：任务与截止/复测日期（从批次总评第四节摘取）
n+3. 结束页：答疑安排 + 鼓励语

四、数据与素材位置
- 所有统计数字：严格引用《01-成绩总表.md》，禁止重算或估算
- 题目、错因、正解、变式：严格引用《讲解课教案》，不得自行改题或编造答案
- 学生作答：仅使用随附的匿名截图，不得出现姓名/学号

五、硬性要求
- 每页一个核心信息、正文 ≤6 行；解题过程分步呈现（分页或分步动画），不整题堆满一页
- 讲稿放入幻灯片备注区，不堆在正文
- 不得新增素材中没有的题目、数据、结论；拿不准的内容留空并标注，不要编造
- 配色与版式全卷统一；图表必须有标题、坐标轴/图例与数据标签

六、验收标准（收到本地文件后据此打开核对）
- 必讲题全部有对应精讲页组；页面总数与页序和第三节约一致
- 抽查数字与《01-成绩总表.md》完全一致；题目/答案与教案一致
- 无学生姓名、学号等身份信息
- 备注区有每页讲稿
- **文件验收**：`.pptx` 能用 PowerPoint/WPS 正常打开且可编辑（文本框、图表可改），
  排版无错位、字体无大面积缺失；PDF 逐页浏览无乱码、无内容裁切
- 文件已保存到 `exports/讲解课PPT-<作业名>.pptx`（或 `.pdf`）
```

### 5.4 派发与验收

- 派发时把简报与三份素材（本地文件路径）一次性给全，并写明本地文件的保存位置与命名，避免制作方猜测；
- 收到子 agent/ppt 技能交付的 `.pptx`/`.pdf` 后，**亲自打开文件**按简报第六节逐条验收：
  发现数字不一致、题目被改、出现身份信息、必讲题缺页、打不开或排版错乱等问题，
  **退回并指明具体页码修改**，直至通过；
- 验收通过后把本地文件路径回填到教案"七、课件"处，并在批次总评"五、后续衔接"登记，再连同文件交付老师。

## 6. 单份/少量作业的简化处理

- **单份作业**（个别辅导场景）：不做班级总评与讲评课；在评分反馈单基础上，
  直接由教学导师角色按错题安排一对一讲评（提示阶梯 + 变式题），错题入学习档案错题本。
- **2 份及以下、或无班级教学场景**：只出反馈单；如老师明确要求，可产出简化版
  "错题讲解清单"（题号、错因、正确思路、变式题 1~2 道），不强制教案与 PPT。
- **混合场景**：一批作业中个别学生问题特殊 → 讲评课解决共性问题，特殊问题走个别反馈与辅导，
  名单在批次总评"改进方向"中记录但不公开点名。
