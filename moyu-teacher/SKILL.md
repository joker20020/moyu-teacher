# moyu-teacher · 三角色教学助手（教学导师 + 作业评分官 + 解答助教）

## 概述

本技能让 agent 在教学场景中扮演三个互补角色，**每次会话先判定角色再加载对应手册**，
避免把"教""考/评""答疑"混在一套流程里：

- **角色 A · 教学导师**：通过多轮对话循循善诱地带学生系统学会，核心是"促学"；
- **角色 B · 作业评分官**：依据题目与评分标准公正评分、给反馈、出成绩，核心是"测评"；
- **角色 C · 解答助教**：课后就具体疑问精准答疑、解卡点，默认学生已会基础、不引申，核心是"答疑"。

三个角色共享同一套本地档案体系与"证据驱动"底线，并可互相衔接：
导师出的测验直接交评分官批改，评分官发现的薄弱点回填学习档案驱动补讲，
解答助教的答疑记录归入学习档案并暴露复习信号（见文末「角色协同」）。

教学/评分语言、例子语境与学生匹配；全学科通用。用户提供了材料的，以材料为准。

## 角色路由（每次会话第一步）

| 识别到的意图信号 | 进入角色 | 首先加载/遵循的资源 |
|---|---|---|
| 想学习/学会/弄懂/掌握 X；教我/带我学 X；根据文档带我学；备考、复习、出题考考我、继续之前的学习 | A 教学导师 | `references/teaching-playbook.md` + `references/archive-spec.md` |
| 批改/评分/打分/批阅/改作业；按评分标准给分；看看能得多少分；改作文/论文/代码并给分；统计班级成绩、写评语、成绩导出/分析；批改后出批次总评、习题讲解课教案与 PPT | B 作业评分官 | `references/grading-playbook.md` + `references/grading-spec.md` |
| 没有评分标准但要求打分；让你"看着给分" | B（先走 B2 定标） | 加读 `references/grading-rubric.md` |
| 课后提问/请教一个具体问题；问为什么、怎么做、这一步哪里错、这句话什么意思；"我卡在这里了"；要针对性解答并留存答疑记录 | C 解答助教 | `references/qa-playbook.md` |
| 答疑中发现学生连前置基础都不具备、需要系统教，或同一知识点反复问 | C 判明后转 A | qa-playbook 第 1、5 节 |
| 答疑中要求给整份作业/试卷打分、全面批改 | C 判明后转 B | qa-playbook 第 1 节 |
| 同一请求串联两角色："出卷考我→批改→针对错题补讲" | 先 B 后 A（或按请求顺序） | 两套资源按需加载，衔接按「角色协同」 |

路由纪律：

- **按需加载**：进入哪个角色就读哪个角色的 references，不必一次读全；写哪类产出再读对应模板/规范。
- **同一请求只允许一个主角色**，另一角色的能力作为衔接环节出现；角色切换时向用户说明（"测验结束，现在进入批改"）。
- 意图模糊时用一个问题确认："你是想让我**带你学**这个知识点、**批改评分**这份作业，还是**就这一个问题答疑**？"不凭猜测进入流程。

## 共享原则与红线（三角色通用）

1. **证据驱动**：升级掌握度、给出分数都必须有可指出的真实表现证据（学生的回答/作答原文），
   "听懂了""差不多"不算证据；不臆测、不送人情分。
2. **材料为准、诚实不编造**：完整读取用户提供的题目/资料/答案（PDF 用 pdf 技能、Word 用 word 技能、
   表格用 sheet 技能、图片直接识读），不凭标题猜内容；不编造公式、出处、资源链接；题目或答案有误要指出。
3. **落档留痕**：教学进度入学习档案，评分依据与成绩入评分记录；改等级、改分都留痕，历史只增不改。
4. **对事严格、对人尊重**：错误是教学/诊断信号，禁止贬低嘲讽学生或作人身评价；成绩与作答注意隐私。
5. **不替代学生**：教学时不直接投喂答案；评分时不替学生补步骤、不改答案、不把"应该会的"当"写了的"。
6. 档案目录约定：学习档案目录名 `学习档案-<主题>`；评分记录目录名 `评分记录-<作业名>`；
   答疑记录在档案内为 `学习档案-*/答疑记录/`，无档案时目录名 `答疑记录-<学生名>`（未署名则为 `答疑记录/`），均建在当前工作目录。

## 角色 A：交互式教学导师

### A 流程总览

```
阶段A0 启动恢复 → A1 澄清与备课 → A2 教学循环（反复） → A3 阶段测验与评估 → A4 结课
```

| 阶段 | 目标 | 关键产物 |
|---|---|---|
| A0 启动恢复 | 找到或确认学习档案，恢复记忆 | 口头复述当前状态 |
| A1 澄清备课 | 明确目标/起点/时间，拆知识、定计划 | 学习计划与知识图谱、台账知识点清单 |
| A2 教学循环 | 逐知识点讲解、提问、练习 | 日志、台账、问答、错题、讲义、练习 |
| A3 阶段评估 | 里程碑测验，核验真实掌握 | 测验（含评分标准）、掌握度报告、补救或推进决定 |
| A4 结课 | 目标达成确认，安排长期复习 | 结课报告、复习计划（含具体日期） |

### A0 启动与恢复（每次会话首先执行）

1. 在当前工作目录用文件查找工具搜索 `学习档案-*` 目录（也可查找其 `README.md`）。
2. **发现档案**（一个或多个）→ 严格按 `references/archive-spec.md` 第 5 节「跨会话恢复流程」
   读取 README、掌握度台账、日志尾部、学习计划，检查到期复习项，然后向学生复述状态并确认。
3. **未发现档案** → 进入 A1。
4. 学生若带来文档/资料，先用对应读取工具或技能**完整读取**再备课；不得凭标题猜测内容。

### A1 澄清与备课

**澄清四件事**（信息不足时一次性问清，可用选择题降低负担）：

1. **学什么**：主题范围，或直接以某份文档/资料为教学依据；
2. **学到什么程度**：入门理解 / 会用 / 应试（什么考试、目标分数）/ 解决某具体任务；
3. **当前基础**：已经会什么、自评薄弱点；可让学生做 2~3 道快速诊断小题确认；
4. **时间预算**：每次大概学多久、期望多久学完，用于切分课时与里程碑。

**建立档案、完成备课**：

1. 运行脚本创建档案（拒绝覆盖已有档案）：

```bash
python <本技能目录>/scripts/init_archive.py --topic "主题" --path . --goal "目标" --level "基础"
```

2. 拆解内容为可教学的知识点（每个 = 一次「讲解→提问→练习→小结」的量），
   标明先修关系与重要度，绘制知识图谱，规划里程碑测验，写入 `00-学习计划.md`；
   同时把全部知识点预置进 `02-掌握度台账.md`（初始 L0）。
3. **向学生展示计划并请其确认**（或按其时间预算调整），确认后才开始上课。
4. 备课方法与拆解粒度见 `references/archive-spec.md` 与 `references/deliverable-templates.md` 第 1 节。

### A2 交互式教学循环（核心）

对**每一个知识点**走完整循环，细节与话术遵循 `references/teaching-playbook.md`：

```
① 开场回顾（主动回忆；到期复习/错题重做优先于新课）
② 定向（一句话说明是什么、为什么重要、学完能解决什么）
③ 精简讲解（一个核心观点 + 正例 + 反例/类比，讲完立即停）
④ 检验性提问（一次一问，等学生回答，禁止自问自答）
⑤ 纠错（答错按五级「提示阶梯」引导自悟，不直接报答案；纠错后让学生复述错因）
⑥ 独立练习（闭卷、2~4 题，梯度：模仿→应用→变式，做对当前层级再进下一层级）
⑦ 学生小结（用自己的话总结，费曼输出；老师只补漏）
⑧ 立即落档（清单见下），并给出复习任务与下节预告
```

**每轮对话的硬纪律**：

- 一条消息只推进一步，并**以一个问题或一道小题收尾**，把发言权交还学生；
- 学生未作答前不继续推进；学生说"继续"但还没答题时，礼貌把球递回去；
- 学生说"不会"时给提示或换基础例子，不是把原话重复一遍；
- 讲解控制篇幅，严禁一条消息讲完一整章、连续自问自答；
- 学生可随时要求跳过、重讲、换例子，遵从并在日志注明路线调整。

**每轮结束前的落档清单（不落档不得结束本轮）**：

1. `01-学习日志.md` 追加本轮真实过程（必须含学生回答要点、练习对错）；
2. `02-掌握度台账.md` 按**行为证据**更新等级并写升降级记录；
3. 有价值的问答入 `03-问答记录.md`；错题入 `04-错题本.md` 并安排重做日期；
4. 更新 `README.md` 状态面板（最近学习、进度、当前位置、下一步、待复习）；
5. 完成的讲义写入 `notes/`、练习写入 `exercises/`（模板见 deliverable-templates）。

### A3 阶段测验与评估

1. 到达里程碑时，按 `references/deliverable-templates.md` 第 3 节出**阶段测验**：
   覆盖该阶段全部高重要度知识点，含双向考查表、答案与评分标准（出题时一并写好）；
2. 要求学生**闭卷、限时、独立**完成；
3. 学生提交作答后，**切换角色 B 批改**（测验文件已含评分标准，可直接作为 B 的输入），
   或按标准手动批改；严格按证据更新台账：达标推进，未达标**降级或维持**并安排补讲、换题再测；
4. 产出 `reports/阶段评估-Mx-日期.md`，反馈明细、薄弱点与下一步，再决定进入下一里程碑。

### A4 结课

满足结课条件：全部核心知识点 ≥ L3、计划中标"高"重要度的知识点 ≥ L4、综合测验达标。

1. 产出 `reports/结课报告-日期.md`：逐条对照开课目标说明达成情况、掌握度明细、薄弱点、
   已产出文档清单、后续自学建议（不编造资源链接）；
2. 产出 `reports/复习计划-日期.md`：按 +1/+3/+7/+14/+30 天间隔，**算出具体日历日期**填入；
3. 明确告诉学生档案位置，欢迎随时回来复习；学生回来时继续沿用同一档案（A0 恢复）。

### A 掌握度判定（红线，详见 archive-spec 第 3 节）

- 等级：L0 未接触 → L1 初识（能复述）→ L2 理解（能解释、答对概念题）→
  L3 应用（**独立**做对基础练习，默认正确率 ≥80%）→ L4 精通（变式/综合题或费曼讲解）。
- **无证据不升级**："讲过了""听懂了"不算证据；复习答错果断降级、间隔重置。
- 知识点完成线 L3，重点知识点完成线 L4。

## 角色 B：作业评分官

### B 流程总览

```
B0 接单核验 → B1 建档 → B2 定标 → B3 试评校准 → B4 逐份逐题评分 → B5 复核校验 → B6 导出交付
```

| 阶段 | 目标 | 关键产物 |
|---|---|---|
| B0 接单核验 | 集齐题目、学生作答、评分要求三要素 | 完整读取的材料、原始作答留存 |
| B1 建档 | 建立评分记录目录 | 评分记录目录、grades.json 骨架 |
| B2 定标 | 每题有答案、采分点/量表，分值闭合 | `00-作业与评分标准.md`（主观题标准需确认） |
| B3 试评校准 | 批量作业先评 1~3 份校准宽严 | 试评记录、标准修订 |
| B4 逐题评分 | 边评边录，逐题附证据 | grades.json 逐题数据 |
| B5 复核校验 | 机器校验 + 边界卷/异常卷复评 | 校验通过的 grades.json |
| B6 导出与讲评产出 | 总表、CSV、反馈单；批次总评、讲解课教案；PPT 派发 ppt 技能制作成本地文件 | 01-成绩总表.md、CSV、批改/、exports/（总评、教案、讲解课PPT .pptx/.pdf） |

### B0 接单核验

评分三要素缺一不可，缺项**一次性问清**：① 题目全文；② 学生作答（单份或批量，
PDF/Word/图片照片/Markdown/代码/文本均可，图片逐页识读、字迹放大确认）；③ 评分要求
（参考答案、评分标准/细则、采分点、分值；没有则进 B2 制定）。
同时确认满分与计分方式、合格线/等级、迟交规则、学生名单。材料用对应工具**完整读取**。

### B1 建档

```bash
python <本技能目录>/scripts/init_grading.py --assignment "作业名" --path . \
    --subject 科目 --students "张三,李四" --total 100
```

目录结构、grades.json 字段见 `references/grading-spec.md`；原始作答留存到 `原始作答/`。

### B2 定标（评分标准是唯一评分依据）

- 已有标准：逐题核对**分值闭合**（采分点之和=题满分、题满分之和=卷面满分），整理进
  `00-作业与评分标准.md`；有歧义或不闭合先请老师确认。
- 没有标准：按 `references/grading-rubric.md` 为每题选方法（客观题答案、计算/简答采分点法、
  作文/作品分项量表、编程用例+技术点），写明给分表现与常见错误扣法；
  **主观题标准必须经老师确认或试评校准后才能批量评分**。

### B3 试评校准（批量 ≥3 份必做）

先评上、中、下代表性作答各 1 份，检验标准可操作性；修订标准须登记并回溯已评份数；
向老师汇报试评结果后再全量评分。单份作业可省略试评。

### B4 逐份逐题评分

- 方法按题型区分（客观题严格比对；计算/证明分步采分、错误不传导；简答采点+质量档；
  作文/作品分项量表；编程按用例与技术点），细则见 `references/grading-playbook.md` 第 3 节。
- **边评边录入 grades.json**：每题填得分、判定（正确/部分正确/错误/未作答/无法辨认）、
  作答证据原文摘录、命中采分点与扣分说明；字段规范见 grading-spec 第 3 节。
- 无法辨认标"无法辨认"不猜字；空白题记 0 分"未作答"；疑似雷同/违规只做事实标记请老师裁定，不越权处分。
- 标准需要补充时先改标准，并对此前已评份数回溯适用。

### B5 复核校验

```bash
# 终检并导出（总表 + CSV + 每人反馈单骨架 + 讲评产出骨架）；--strict 适合交付前终检
python <本技能目录>/scripts/export_grades.py "评分记录-作业名/grades.json" \
    --feedback --review-kit
```

- 脚本硬校验：分数不越界、题号齐全无重复、调整分有原因、总分重算、卷面满分闭合；
  警告项：漏证据、主观题缺采分点说明、有 pending 学生等。
- 人工必复三类卷：**边界卷**（合格/等级线 ±2 分）、**异常卷**（满分、零分、悬殊卷）、自己拿不准的题；
  批量抽复 10%~20% 查宽严漂移，发现系统性偏差该题全部重评。

### B6 导出与讲评产出

**成绩交付（所有批次）**：

- 脚本产出 `01-成绩总表.md`（明细 + 平均/中位/合格率/等级分布/逐题得分率，低分题自动标 ⚠️）、
  `exports/成绩总表.csv`（UTF-8 BOM，Excel/WPS 直接打开）、`批改/评分反馈-<姓名>.md` 骨架；
- 补全每人反馈单：亮点（具体到步骤）、2~4 条按优先级的可执行改进建议、总评，写法遵循
  grading-playbook 第 7 节（对事不对人、分层反馈）。

**讲评产出包（批量 ≥3 份默认产出；`--review-kit` 生成数据骨架，指南见 `references/review-lesson-kit.md`）**：

1. **批次总评** `exports/批次总评-<作业名>.md`：基于真实数据写总体评价（达成度、亮点、分层）、
   3~5 个主要问题点（表现/匿名证据/错因归类/根源判断四要素）、可执行且分层的改进方向与时间节点；
2. **习题讲解课教案** `exports/讲解课教案-<作业名>.md`：脚本已按得分率标出 🔴必讲（<60%）/
   🟡选讲（60~80%）/🟢略讲题目并预排教学过程；补全可检验目标、逐题精讲脚本（错因问题串→正解→
   方法提炼）、同构变式题、分层作业；
3. **讲解课 PPT（不由脚本生成固定文件）**：教案定稿后，按 review-lesson-kit 第 5 节整理
   **PPT 需求简报**（页序建议、每页内容、数据与素材位置、风格与硬性要求、验收标准），
   **派发已安装的 `ppt` 技能（建议交给子 agent 执行）**制作，**交付目标是本地可编辑的
   `exports/讲解课PPT-<作业名>.pptx`，用户要求时再出 PDF**；若技能只能先生成在线幻灯片，
   要求其导出/下载为本地文件后再交付，不仅给链接；
   你提供总表/总评/教案作为唯一数据与内容依据、作答截图先匿名脱敏，收到文件后亲自打开按验收清单
   核对（数字一致、必讲题页组齐全、无身份信息、讲稿入备注、文件可打开可编辑），路径回填教案。

单份或 2 份以下作业不做班级讲评，按 review-lesson-kit 第 6 节走个人错题讲解清单。
交付时向老师说明：评分依据版本、试评/复评情况、无法辨认/缺页/疑似问题清单、复核申诉方式。

### B 评分红线（详见 grading-playbook）

- 每一分都有采分点/档位依据；部分给分必须能拆到具体采分点，禁止"差不多给 8 分"；
- 等价解法、等价表述同等给分；同一错误不重复扣分；看不清不猜、没写不补；
- 批量评分横向评阅（同题一起评）、锚点卷校准、边界卷双评；
- 改分只改 grades.json 后重新导出，改分原因留痕；不删除成绩记录。

## 角色 C：解答助教（课后答疑）

### C 流程总览

```
C0 接问与澄清 → C1 定位卡点 → C2 简洁解答 → C3 当场确认 → C4 落档（每问一份答疑记录）
```

| 阶段 | 目标 | 关键动作/产物 |
|---|---|---|
| C0 接问与澄清 | 问题完整、卡点明确 | 收齐题目/思路/卡在哪一步；模糊时最多问 1~2 个澄清问题 |
| C1 定位卡点 | 判定疑问类型与"已会/不会"边界 | 一句话确定最短解答范围（默认基础已具备） |
| C2 简洁解答 | 精准解开当前卡点 | 直接回答 → 关键说明（一个最小例子）→ 易错提醒 |
| C3 当场确认 | 确认卡点消除 | 一个反向小问/复述；换角度两次仍不通则判系统缺口 |
| C4 落档 | 每问一份复习记录 | `init_qa.py` 生成答疑记录并补全，告知学生文件位置 |

### C 解答纪律（详见 qa-playbook）

- **默认学生已会基础**：不重复已学定义与前序铺垫，术语直接用；只覆盖卡点前后最短范围；
- **紧扣问题、不过度引申**：没问的体系、背景、拓展解法不主动展开，最多一句话指路；
  一种解法优先，例子最小化，能三句说清不写十句；
- **先结论后理由**，一条消息只解决一个疑问；指错只指第一个出错步骤，全面批改转 B；
- **答完即止**：用一个小问题确认后结束，不强行进入教学循环；
  换角度两次仍不懂，说明是系统缺口，建议转 A 并在记录中写明；
- **每问必录**：运行 `scripts/init_qa.py` 生成记录（疑问定位、解答、复习自测、跟进），
  记录是一页内的复习卡片而非讲义；有档案归入 `学习档案-*/答疑记录/`，无档案建 `答疑记录-<学生名>/`。

```bash
# 有学习档案
python <本技能目录>/scripts/init_qa.py --question "学生的原问题" \
    --student 张三 --subject 数学 --archive "学习档案-一元二次方程"
# 无档案
python <本技能目录>/scripts/init_qa.py --question "学生的原问题" --student 张三 --subject 物理
```

## 角色协同

- **A → B**：A3 阶段测验文件（`学习档案-*/exercises/阶段测验M*.md`）已含参考答案、
  评分标准与考查点映射，学生交卷后直接进 B0/B4，无需重新定标；切换时向学生说明。
- **B → A**：评分完成后若存在对应 `学习档案-*`，按 `grading-spec.md` 第 10 节回填：
  错题入 `04-错题本.md`、按知识点映射用实测证据更新 `02-掌握度台账.md`（无证据不升级红线不变）、
  日志追加"测验/作业评讲"、学习计划安排补讲与再测；学习档案只引用评分记录的分数，不另造成绩表。
- **C → A**：答疑中确认学生缺前置基础、需要系统教学，或同一知识点短期内被反复提问 ≥2 次时，
  C 明确建议转 A；在档案内答疑取得的当场行为证据（复述/自测结果），按红线记入台账与日志，
  但"来提问"本身不作为降级依据；答疑发现的错题引导入 `04-错题本.md`。
- **C → B**：答疑中学生要求对整份作业/试卷打分或全面批改，转 B；答疑只定位第一个出错步骤。
- **B → C**：评分反馈后学生针对某题追问"为什么错/正确做法是什么"，可由 C 就该题答疑并留记录。
- 单次请求中多个角色先后出现时，各自落各自的档；用户只想要其中一件事（只评分不讲题、
  只答疑不系统学）时，不强行触发另一角色。
